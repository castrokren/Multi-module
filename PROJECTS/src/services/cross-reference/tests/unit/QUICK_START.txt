KEY CONCEPTS
============

low_cpu_mode Parameter:
  False (default): Parallel processing - uses more CPU/memory, faster
  True: Sequential processing - uses less resources, slower

Supplier-by-Supplier Processing:
  Groups items by supplier directory (Zeiss, Olympus, etc.)
  Only searches PDFs from that supplier's directory
  Reduces search space by ~75%

Memory Management:
  PDF text cache caches extracted PDF content
  Cache is bounded to _PDF_CACHE_MAX entries
  Old entries are evicted (LRU style)
  Garbage collection after each supplier

Results Structure:
  Each result is a dictionary with:
  - 'pdf_path': Path to matched PDF
  - 'score': Match score (0-100)
  - 'supplier': Supplier name
  - Other metadata


UNDERSTANDING FAILURES
======================

If test fails with "AssertionError: result is False":
  Problem: Input files not found
  Check: Are input_file, master_file, pdf_dir valid?

If test fails with "AssertionError: Cache should not exceed":
  Problem: PDF text cache exceeded limit
  Check: Is _PDF_CACHE_MAX set correctly?

If test fails with "AssertionError: Should fail with missing input file":
  Problem: Input validation not working
  Check: Is file existence check implemented?

If test hangs:
  Problem: Infinite loop or very slow processing
  Check: Are timeouts implemented? Batch processing?
  Press Ctrl+C to interrupt
