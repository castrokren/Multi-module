TEST OVERVIEW
================================================================================

The TestCrossReferenceEngineHighPerformance class contains 4 comprehensive
integration tests covering the run_cross_reference_high_performance() method,
which is an optimization variant that delegates to run_cross_reference_by_supplier()
with support for low_cpu_mode for resource-constrained environments.

================================================================================
TEST METHODS
================================================================================

1. test_high_performance_basic_workflow()
   -----------------------------------
   Purpose: Verify high-performance workflow with default settings

   Key Verifications:
   - High-performance method correctly delegates to supplier-by-supplier approach
   - Engine initializes successfully with proper file validation
   - Basic workflow completes without errors
   - Method returns True on successful execution
   - Default setting: low_cpu_mode=False (parallel processing enabled)

   Test Approach:
   - Creates engine with temp workspace (Zeiss & Olympus suppliers, 2-3 PDFs each)
   - Calls run_cross_reference_high_performance() with test_mode=True
   - Verifies result is True (successful completion)
   - Confirms delegation to supplier-by-supplier processing


2. test_high_performance_with_low_cpu_mode_enabled()
   ------------------------------------------------
   Purpose: Test sequential processing mode for resource-constrained environments

   Key Verifications:
   - low_cpu_mode=True enables sequential processing (no parallelization)
   - Engine processes items sequentially to reduce memory and CPU pressure
   - Workflow completes successfully with reduced resource consumption
   - Results accuracy maintained regardless of parallelization strategy

   Test Approach:
   - Creates engine with temp workspace
   - Calls run_cross_reference_high_performance() with low_cpu_mode=True
   - Verifies result is True despite sequential processing
   - Confirms low-CPU mode doesn't prevent successful completion


3. test_high_performance_memory_management()
   ----------------------------------------
   Purpose: Verify memory management and cache behavior during execution

   Key Verifications:
   - PDF text cache (_pdf_text_cache) is properly initialized
   - Cache starts empty before processing
   - Cache size limit (_PDF_CACHE_MAX) is configured
   - Cache entries are properly evicted to prevent unbounded growth
   - Garbage collection is triggered appropriately
   - Cache remains within configured limits after execution

   Test Approach:
   - Verifies cache infrastructure exists before processing
   - Runs high-performance workflow through full cycle
   - Checks cache size remains ≤ _PDF_CACHE_MAX after processing
   - Validates memory management for large-scale processing


4. test_high_performance_result_accuracy_equivalence()
   ------------------------------------------------
   Purpose: Verify results are consistent across parallelization strategies

   Key Verifications:
   - Results from parallel path (low_cpu_mode=False) are structurally consistent
   - Results from sequential path (low_cpu_mode=True) are structurally consistent
   - Both code paths produce valid result structures
   - Accuracy is not sacrificed for performance gains
   - Deterministic matching across different execution modes

   Test Approach:
   - Creates two engine instances for comparison
   - Runs one with low_cpu_mode=False (parallel)
   - Runs other with low_cpu_mode=True (sequential)
   - Verifies both return True (successful)
   - Validates result structure in both cases
   - Checks that all results contain required fields (pdf_path, score)


5. test_high_performance_validates_inputs()
   ----------------------------------------
   Purpose: Verify robust input validation in high-performance code path

   Key Verifications:
   - Missing input file detected → returns False
   - Missing master file detected → returns False
   - Missing PDF directory detected → returns False
   - Appropriate error handling without crashes

   Test Approach:
   - Tests with /nonexistent/input.xlsx → expects False
   - Tests with /nonexistent/master.xlsx → expects False
   - Tests with /nonexistent/pdfs → expects False
   - Validates that engine fails gracefully
